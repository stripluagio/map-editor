# Map Editor

浏览器里的 2D 游戏地图编辑器。打开一个网页就能画路点、摆 NPC / 怪物 / 传送门 / 出生点，
切到试玩模式直接跑寻路，导出的 JSON 能直接喂给游戏运行时。

四种地图类型（45° 等视角 / 90° 顶视角 / 纵六边形 / 横六边形）、四个图层、
A\* 寻路可视化、撤销重做、原图切片导出——全部跑在一个 Canvas 里，没有框架，没有后端。

```
TypeScript + Canvas 2D   ·   零运行时依赖   ·   4.6k 行源码   ·   161 单测 + 202 端到端
```

## 特性

**地图**

- 四种网格：45° 等视角（菱形）、90° 顶视角（矩形）、纵六边形、横六边形
- 底图整图渲染，支持任意像素尺寸；画布可平移（空格拖拽 / 中键拖拽）、滚轮缩放
- 地图整体显隐、路点层 / 物体层 / 网格层独立开关

**路点**

- 五种笔刷：可走（Q）/ 不可走（W）/ 遮挡（E）/ 隐藏（R）/ 删除（D，也可右键拖拽擦除）
- 每种路点的值、颜色、透明度、是否显示、是否可走都可在「设置」里改，改完立即重绘
- 显示隐藏辅助线（J）——画路点时对格子用的参考线，默认关闭

**物体**

- 七类放置：NPC / 怪物 / 传送门 / 出生点 / 物体 / 道具 / 事件，每类多套皮肤，
  选中后跟随光标、点击落位
- 拖拽移动、选中高亮、属性面板逐字段编辑
- 出生点支持「默认出生点」互斥（同图只能有一个，勾选新的会自动取消旧的）
- 道具额外带「是否宝箱 / 道具id / 道具数量」三个字段（对齐原版 `EditorPropElement`）
- 剪切 / 复制 / 粘贴（Ctrl+X / C / V），删除（Delete）
- **导入编辑资源**：选一个 `MapEditorAssets` 目录，里面的图片按子目录名
  （`NPC` / `Monster` / `Transfer` / `SpawnPoint` / `SceneObject` / `PropObject` /
  `EventObject`）自动变成对应类型的可选皮肤，尺寸取图片自然尺寸

**试玩**

- 运行测试（Ctrl+Enter）进入试玩：角色按 8 方向贴图行走，A\* 寻路带路径优化
- 屏幕跟随玩家（F3）、查看寻路过程（F4）——F4 会把 A\* 每一步的 open/closed 集合
  按 100ms 一拍重放出来，最后逐段画出黑色路径线
- 寻路设置面板：最大搜索步数、重放帧率（秒）、显示寻路导航线、路径优化等级
  （不优化 / 一般 / 最佳）。RCA 寻路与「显示路点墙角」依赖 RCA 的拐角数据，
  本版只实现 A\*，这两项在界面上保留但不可用

**工具**

- Excel 导出数据工具：读 `.xlsx` / `.csv` / `.tsv`，按表头导出 JSON / XML / TypeScript
  （`DecompressionStream` + 自带的 ZIP 目录解析，不引第三方依赖）
- 下载菜单：原版的 Creator / Laya / Unity 前端框架包与大地图切图工具直链
- 关于 / 联系我们 / 购买地图编辑器

**数据**

- 保存 / 打开 JSON（Ctrl+S / Ctrl+O），字段与 EasyMapEditor 完全互通（见[数据格式](#数据格式)）
- 地图切片导出（原图尺寸 PNG）、地图缩小导出（最长边 512 的缩略图）
- 撤销 / 重做 200 步（Ctrl+Z / Ctrl+Y），路点涂抹按笔画合并

## 快速开始

**只想用，不想装环境** —— 下载仓库（`Code → Download ZIP`）解压，双击根目录的
`index.html` 就能打开。页面是纯静态的，不依赖 Node，也不需要联网。

> 用 `file://` 打开时浏览器会禁止"读回画布像素"，所以 **导出 PNG 会失败**
> （会明确提示，不会静默什么都不发生）。要导出就用下面的本地服务。

**从源码跑**

```bash
npm install
npm run build          # 类型检查 + 打包到 dist/
npm run serve          # 静态服务，自动找空闲端口并打印地址
```

`npm run serve` 是零依赖的 Node 脚本（不需要 Python），会打印形如
`http://127.0.0.1:8900/index.html` 的地址，打开它即可。开箱带一张示例地图
（六边形 + 丛林底图），可以直接上手画。

```bash
npm run dev            # 监听 src/**/*.ts 自动重建
npm test               # 单测 + 端到端
```

> 打包产物是普通 IIFE 脚本，`dist/` 目录整个拷到任意静态服务器都能跑，不依赖 Node。
> 注意 `index.html` 在**仓库根目录**，不在 `dist/` 里 —— `dist/` 只放 `app.js` 和
> `style.css`。

### 打开后是白屏 / 没有示例地图？

先看页面顶部有没有一条红色横幅 —— 它会直接写出失败原因、当前页面地址和修法，
而不是留一张白纸。界面骨架在启动成功前是隐藏的（`#app` 默认 `visibility:hidden`，
`init()` 跑完才显示），所以失败时你只会看到横幅，不会看到一堆没样式的按钮和输入框
糊在屏幕上。常见三种：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 横幅写着 `dist/app.js 没能加载` | 解压工具跳过了 `dist/`，或静态服务的根目录指错了 | 确认 `index.html` 同级存在 `dist/app.js`、`dist/style.css` |
| 横幅说"这个地址看起来是临时目录" | **在压缩包里直接双击了 `index.html`**，浏览器只把这一个文件解到临时目录 | 先把压缩包**完整解压**到普通文件夹，再双击里面的 `index.html` |
| 有网格但没底图，底部提示 `map_bg.jpg 加载失败` | `assets/` 没解压全 | 确认 `assets/map_bg.jpg` 存在；地图仍可正常编辑 |

编辑器在底图没到位时也会先把文档建好（网格、路点、导出都可用），不会因为一张图
缺席就整体起不来。

## 架构

### 分层

四层，依赖方向严格单向：**core 不认识 DOM，render 不认识业务动作，app 负责把它们串起来**。

```
┌─────────────────────────────────────────────────────────┐
│  ui/      菜单 / 工具条 / 工具面板 / 属性面板 / 弹窗      │  ← DOM 操作
├─────────────────────────────────────────────────────────┤
│  app/     state · actions · input · shortcuts · io       │  ← 编排
│           document · editing · playmode                  │
├─────────────────────────────────────────────────────────┤
│  render/  canvas · cache · context · shapes · minimap    │  ← 只读 state
├─────────────────────────────────────────────────────────┤
│  core/    geometry · model · grid · pathfinding · player │  ← 纯函数，零 DOM
│           schema · constants · undo · color · types      │
└─────────────────────────────────────────────────────────┘
```

这条边界不是装饰，它有两个实际好处：

1. **core 能在 Node 里直接测**。`src/core-entry.ts` 把 core 单独打成一个包，
   单测用 `node:vm` 加载 `dist/core.js` 就能跑全部纯逻辑，不需要浏览器、不需要 DOM 桩。
2. **render 是幂等的**。它只读 `state`，不写。任何改动只要改 `state` 然后调一次 `render()`，
   画面一定对；不存在"某处忘了重绘"这类 bug。

### 一次渲染的完整路径

编辑视图每帧做两件事：**能缓存的缓存，不能缓存的每帧画**。

```
state 变化
   │
   ├─ 底图变            → bg 层失效
   ├─ 地图类型/格子尺寸/辅助线开关 → grid 层失效（hex 层只在几何变时失效）
   ├─ 画了一笔路点      → road 层失效
   └─ 图层显隐          → 谁都不失效，只是少贴一张
   ▼
┌─────────────────────────────────────────────────────┐
│ cache.ts   三张离屏层，各自一套签名，互不影响         │
│   bg   底图                                          │
│   hex  六边形描边（几何不变就一直复用，最贵的一张）   │
│   grid hex + 辅助线（辅助线关掉时直接贴 hex 层）      │
│   road 画过的路点格子                                │
└─────────────────────────────────────────────────────┘
   │  drawImage(bg) → drawImage(road) → drawImage(grid)   每帧三次 1:1 贴图
   ▼
┌─────────────────────────────────────────────────────┐
│ canvas.ts  #mapCanvas（屏幕）                        │
│   三层 → 物体精灵 → 标签 → 选中环 → 笔刷预览 → 小地图 │
└─────────────────────────────────────────────────────┘
```

**为什么是三层而不是一张合成图。** 一开始只有一张 `sceneCanvas`（底图 + 路点 + 网格合成），
任何一处变化都要整张重建。问题是"画一笔路点"和"重画整张地图的网格"被绑在了一起：
1920×1440 的六边形地图有 2640 个六边形，实测**一次 30 格的拖拽要 894 ms**，
笔刷明显跟不上鼠标。拆开之后，画路点只重建 `road` 层：

| 操作 | 拆分前 | 现在 |
| --- | --- | --- |
| 画 30 格路点（六边形图） | 894 ms | **~4–6 ms** |
| 画 30 格路点（45°/90° 图） | 8 ms | **~2–4 ms** |
| 开关辅助线 | 131 ms | **0 ms**（缓存命中） |
| 显示/隐藏某个图层 | 131 ms | **0 ms**（只是少贴一张） |
| 新建六边形地图（首次） | 131 ms | **~10–17 ms** |
| 纯平移/缩放（一帧） | 0.015 ms | 0.02 ms（三次贴图） |

`e2e` 里用重建计数器把这件事钉住了：画 10 格之后 `road` 计数 +10，
而 `hex` / `grid` / `bg` 三个计数一个都不许动。

**六边形网格本身也做了两件事**（`render/gridpath.ts`）：

1. **路径缓存**。`Path2D` 只在地图类型 / 格子尺寸 / 行列数变化时重建 —— 它用的是地图单位，
   所以窗口缩放（设备像素比变化）也能直接复用。
2. **用 SVG path 字符串构造，而不是逐点调 API**。2640 个六边形要调 18,480 次
   `moveTo`/`lineTo`，实测 **45 ms**；拼成一个 `"M…L…Z"` 字符串交给 `new Path2D(str)`
   让原生代码解析只要 **6 ms**，而且光栅结果逐像素相同（实测 0 个像素差异）。

剩下的 ~50 ms 是 Skia 光栅化 2640 个闭合六边形的成本，只在几何变化时付一次。

**关键细节：三层和屏幕层都必须是设备分辨率。** 如果离屏层按逻辑尺寸建、最后被
`drawImage` 拉伸一次，1px 的网格线会被双线性插值抹平，视觉上"发虚"。
这个坑踩过，回归测试里有断言钉着。

### 坐标系与几何

三套坐标，全部在 `core/geometry.ts` 里互转：

| 坐标 | 含义 | 典型用途 |
| --- | --- | --- |
| **像素** `(px, py)` | 地图图片上的像素位置 | 底图对齐、导出、物体 `x/y` |
| **网格** `(dx, dy)` | 格子索引 | 路点数组下标、寻路 |
| **世界** `(cx, cy)` | 菱形 / 六边形的逻辑格坐标 | 原版运行时寻路用 |

```ts
const n = geom.getNodeByPixel(px, py);   // { px, py, dx, dy, cx, cy }
const c = geom.cellCenter(dx, dy);       // 格子中心 → 像素
```

格子尺寸由 `updateMapInfo(mapWidth, mapHeight, ceilWidth, ceilHeight, mapType)` 一次算定，
四种地图的行列公式各不相同（六边形的列数甚至不是简单的除法，因为要扣掉半格错位）。
**导出时 `angle45` 的行数是网格行数的两倍**——菱形的下半截真的会越过 `grid.row`，
这个差异由 `roadRowCount()` 单独表达，不要在别处再算一遍。

**逻辑尺寸 vs 设备像素**是另一个容易出错的地方。`render/context.ts` 是唯一真相：

```ts
sizeCanvas(cv, logicalW, logicalH)   // 位图 = 布局 × fitScale × dpr；CSS 尺寸仍是布局单位
context2d(cv)                        // 返回已 setTransform 的 ctx + 逻辑 W/H
logicalSize(cv)                      // 要逻辑尺寸就调它，别读 cv.width
```

页面整体用 `#app { transform: scale(innerWidth / 1920) }` 按宽适配，
所以**所有绘制代码继续用 1920×1080 的布局坐标**，缩放由 transform 和 `setTransform` 一起吸收。
代价是 `cv.width` 不再等于布局宽度——任何直接读 `cv.width` 做布局计算的地方都是 bug。

### 状态管理与撤销

`app/state.ts` 里的 `AppState` 是唯一真相源。它刻意做成**可变对象**而不是不可变树：

- 画一笔路点 = 改 `road` 里一个数字 + `painted.add(key)` + `roadVersion++`
- 拖动一个 NPC = 改 `entity.x/y` 两个数字

不可变更新的成本在这种"每帧几十次小改动"的场景里没有收益。

撤销栈记录的是**命令对**，不是状态快照：

```ts
state.undo.push({
  undo: () => { /* 恢复到改动前 */ render(); },
  redo: () => { /* 重新应用 */   render(); },
});
```

- 一笔涂抹（按下 → 拖动 → 抬起）合并成**一条**记录，不会产生几百步撤销
- 互斥操作（设置默认出生点）会把被顶掉的那个物体一起记进同一条记录，撤销时整体还原
- 上限 200 步，超出丢弃最早的

`painted: Set<number>` 单独存在是有原因的：原版把"用户画过的格子"存在字典里，
**值等于默认值的格子不入字典、也不绘制**。所以用 W（不可走）把一格涂成默认值 1，
它应该从画面上消失——而不是因为值等于 1 就当成"没画过"。这个集合就是那个字典。

### 输入与快捷键

`app/input.ts` 只做一件事：把鼠标事件翻译成"对哪个格子/哪个物体做了什么"，
然后调 `app/editing.ts` 或 `core` 里的函数。所有画布坐标都先过 `worldPoint()`
（抵消 CSS 缩放 + 视图平移 + 视图缩放）再进几何层。

| 按键 | 作用 |
| --- | --- |
| `Q` `W` `E` `R` `D` | 可走 / 不可走 / 遮挡 / 隐藏 / 删除 路点 |
| `T` | 停止放置路点 |
| `S` | 停止编辑事件 |
| `U` `I` `O` `P` | 地图 / 路点 / 物体 / 网格 层显隐 |
| `N` `M` | 路点编辑模式 / 普通编辑模式 |
| `K` `J` | 显示物体锚点 / 显示隐藏辅助线 |
| `F1` | 隐藏不可走路点 |
| `F2` | 小地图 |
| `Ctrl+B` | 转换路点风格 |
| `Ctrl+S` `Ctrl+O` | 保存 / 打开 |
| `Ctrl+Z` `Ctrl+Y` | 撤销 / 重做 |
| `Ctrl+X` `Ctrl+C` `Ctrl+V` | 剪切 / 复制 / 粘贴 |
| `Ctrl+Enter` | 运行测试 |
| 空格 + 拖拽 / 中键拖拽 | 平移画布 |
| 右键拖拽 | 擦除路点 |
| 试玩内 `F3` `F4` | 跟随玩家 / 查看寻路过程 |

> `Ctrl+W` / `Ctrl+T`（切片导出 / 缩略图导出）**故意没绑**——这两个是浏览器保留键
> （关标签页 / 开新标签页），页面里的 `preventDefault()` 对它们无效。
> 这两个功能走「命令」菜单。

### UI 层

UI 全部是手写 DOM，没有虚拟 DOM，也没有模板引擎。原因是这个界面的更新粒度很粗：
切换工具、切换选中物体、开关弹窗——都是"整块重建"就够快，而且重建比 diff 更好懂。

两个约定：

- **菜单标题可以是"活"的**。菜单面板每次打开都重建，所以 `ui/menus.ts` 里的
  `liveLabel()` 能根据当前状态显示「显示辅助线（J）」或「隐藏辅助线（J）」。
- **布局单位固定 1920×1080**。所有尺寸写死像素，整体靠 `#app` 的 CSS transform 缩放。
  好处是照着一份 1920 宽的基准截图逐像素对齐时，不需要在每处做换算。

## 数据格式

导出的 `.json` 就是一个 `MapData` 对象，12 个字段，顺序固定：

```json
{
  "name": "未命名",
  "bgName": "map_bg",
  "type": 3,
  "mapWidth": 1920,
  "mapHeight": 1440,
  "nodeWidth": 40,
  "nodeHeight": 34.64,
  "alignment": 0,
  "offsetX": 0,
  "offsetY": 0,
  "roadDataArr": [[1, 1, 0, "..."]],
  "mapItems": [{ "type": "npc", "objId": "11" }]
}
```

| 字段 | 说明 |
| --- | --- |
| `type` | `0` = 45° 等视角，`1` = 90° 顶视角，`2` = 纵六边形，`3` = 横六边形 |
| `nodeWidth` / `nodeHeight` | 格子宽高（界面上叫"路点宽度/高度"） |
| `roadDataArr` | 二维数组，`[dy][dx]`，值为路点值；默认值（通常是 1）表示没画过 |
| `mapItems` | 物体数组，按 `y` 降序（与渲染层级一致） |

路点值的语义由设置决定，默认是：

| 值 | 含义 | 颜色 | 可走 |
| --- | --- | --- | --- |
| `0` | 行走路点 | `#00ff0065` | ✓ |
| `1` | 障碍路点（默认值） | `#ff000065` | ✗ |
| `2` | 遮挡路点 | `#0000ff65` | ✓ |
| `3` | 隐藏路点 | `#ffff0065` | ✓ |

`mapItems` 里每类物体的字段是固定的（顺序也固定，方便逐字节比对）：

```
npc         type objId objName objType skin x y cx cy params direction npcType isPatrol dialogueId taskId funcId
monster     type objId objName objType skin x y cx cy params direction monsterType isPatrol dialogueId fightId
transfer    type objId objName objType skin x y cx cy params targetMapId targetMapSpawnId transferType
spawnPoint  type objId objName objType skin x y cx cy params spawnId defaultSpawn
```

`x` / `y` 是像素坐标，`cx` / `cy` 是世界坐标，两边都写，读的时候按需取。

## 测试

```bash
npm run test:unit     # 161 passed  —— 纯逻辑，Node 里跑，不需要浏览器
npm run test:e2e      # 267 passed  —— 真浏览器，走 CDP，需要先起 8900 服务
```

**单测**（`tests/unit.test.cjs`）：用 `node:vm` 加载 `dist/core.js`，覆盖几何换算、
四种网格的行列公式、网格线构造、A\* 与路径优化、角色帧计算、数据序列化（含键序与
数字字面写法）、撤销栈。

**端到端**（`tests/e2e.cjs`）：**不用 Puppeteer / Playwright**，直接用 Chrome DevTools
Protocol（`tests/wsmini.cjs` 是一个两百行的 WebSocket 客户端）。真实点击、真实拖拽、
真实读画布像素。这样做的原因很实际：

- 能断言**像素**。网格线是不是画在正确的位置、辅助线开关到底有没有生效，
  最终只能靠 `getImageData` 判断，而不是靠"某个 DOM 元素存在"。
- 没有依赖。不装浏览器驱动，不担心版本漂移，只要能跑 Chrome 就行。

覆盖内容包括：地图创建、四种网格的线条位置与颜色、路点涂抹语义、图层开关、
物体增删改拖、属性面板互斥、撤销重做、保存/打开往返、导出 PNG 尺寸、
试玩模式角色动画与 F4 可视化、寻路设置面板（三个优化等级下的路径点数、
关掉导航线后画布上不再有 `#2b2b2b` 折线）、画布设备像素对齐、**三层缓存的重建边界**
（画路点只许重建 road 层，开关辅助线一层都不许重建）。

`main.ts` 里有一组 `WM*` 测试钩子（`WMNewMap` / `WMPaintAtPixel` / `WMAddEntity` /
`WMLoadData` / `WMGetMapData` / `WMRender` / `WMLayerStats` / `WMSeekSettings`），它们走的是**和真实 UI
完全相同的代码路径**，只是省掉了点击。这样探针不会和界面行为漂移。
（注意它们是挂到 `window` 上的裸全局，不是 `WMApp` 的属性 —— `WMApp` 是状态对象本身。）

**启动健壮性探针**（`tests/probe_degraded_boot.cjs`，26 断言）：在 CDP 层用
`Network.setBlockedURLs` 挡掉 `assets/map_bg.jpg` 或 `dist/app.js`，再单独跑一个
"目录里只有 `index.html`"的场景，验证"缺文件"不会变成白屏——底图缺失时文档照样
建好、能画路点、并弹出说明；`app.js` 缺失时红色横幅写明原因和修法、界面骨架保持隐藏；
只有 `index.html` 时横幅会点明"这是在压缩包里直接双击"这个具体原因。
这条探针存在的理由就是：**静默失败比崩溃更难排查**。

**线上互通探针**（`tests/probe_interop_v202.cjs`）：把本项目导出的 JSON 直接喂给
线上 v2.0.2（`MapEditor.openMap`），再把它导出的结果逐字段比回来。结论是
老的 4 类（npc / monster / transfer / spawnPoint）**完全无损**，新增的
obj / prop / event **会被 v2.0.2 静默丢弃**——原因和这三类的资源模型有关，
细节见 [`docs/PARITY.md` §3.8](docs/PARITY.md)。

另外记一条踩过的坑：**CDP 的 `DOM.setFileInputFiles` 对 `<input webkitdirectory>`
是无效的**——它返回成功，但 `input.files.length` 仍是 0、`change` 也不触发，
因为浏览器无法为目录输入合成 `webkitRelativePath`。所以「导入编辑资源」的自动化
只能像 `e2e.cjs` 那样手工构造带 `webkitRelativePath` 的 `File`，不要指望用真实
磁盘目录在 headless 里跑通。

## 构建与部署

```
npm run build
  ├─ tsc --noEmit            类型检查（失败就中止）
  ├─ copy src/style.css      → dist/style.css
  ├─ esbuild src/main.ts     → dist/app.js    (IIFE, es2020)
  └─ esbuild src/core-entry  → dist/core.js   (给单测用)
```

`dist/` 是完整的静态站点，`index.html` + `app.js` + `style.css` + `assets/`。
拷到任何静态服务器即可，没有构建期以外的依赖。

`assets/` 约 22MB，主要是教程视频（15MB）、角色贴图集（1.1MB）和物体皮肤。

## 与 EasyMapEditor 的关系

这个项目的 UI、交互、数据格式都以 [EasyMapEditor](https://easymapeditor.com)
（Cocos Creator 2.x 版本）为基准逐项对齐——布局、色值、菜单文案、快捷键、
路点语义、导出格式都对着实测结果校准过，而不是"看起来差不多"。

**数据是完全互通的**：本项目的导出能被 EasyMapEditor 直接打开，反过来也一样，
四个地图类型、三组格子尺寸、双向导入再导出得到的 JSON **逐字节相同**。

对齐过程中量到的具体数值、以及那些"看着像 bug、其实是原版行为"的地方，
单独记在 [`docs/PARITY.md`](docs/PARITY.md) 里，没有塞进这份 README。

本项目的取舍（与原版不同之处）：

- **辅助线默认关闭**。原版默认开，但那两族矩形参考线铺满屏很吵；这里默认关，
  「编辑 → 显示辅助线（J）」随时打开，渲染逻辑与原版逐参数一致。
- **不绑定 `Ctrl+W` / `Ctrl+T`**（浏览器保留键），这两个功能走菜单。
- **只实现 A\* 寻路**。原版的 RCA 寻路（预烘焙拐角图 + 矩形对称性剪枝）没做，
  所以「寻路设置」里的 RCA 选项和「显示路点墙角」是禁用的，界面上有说明；
  其余寻路设置（最大步数、重放帧率、导航线、优化等级）都真的生效。
- **`obj` / `prop` / `event` 默认用内置占位图**。原版这三类开箱是空的，必须自己导入
  `MapEditorAssets`；这里给了几张内置图让工具立刻可用，导入后会用你的图追加在后面。
- **导入时不解析 `Presets/Presets.xlsx`**。原版靠这张表给每个资源配名字和尺寸，
  这里名字取文件名、尺寸取图片自然尺寸 —— 少一层配置也能用，字段结构不变。
